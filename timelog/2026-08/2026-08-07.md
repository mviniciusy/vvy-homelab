# Timelog — 2026-08-07

## Tarefa 1: Diagnóstico e correção de falhas de backup (PATH do cron + token OAuth)

### Contexto

Usuário reportou suspeita de que o backup não estava rodando. Verificação
confirmou: 3 scripts de backup do host vvy falhando há 3 dias (05-07/08),
todos pela mesma causa-raiz.

### Diagnóstico

**Causa raiz #1 — PATH do cron (causa principal):**

O `PATH` do cron é `/usr/bin:/bin` (confirmado capturando `env` de job cron).
Mas `pvesm` está em `/usr/sbin/pvesm` e `pct` está em `/usr/sbin/pct`.

Os 5 scripts de backup do host (`snapshot_hermes.sh`, `snapshot_semanal.sh`,
`snapshot_mensal.sh`, `backup_proxmox_config.sh`, `sync_root.sh`) usavam
`pvesm` e `pct` sem path absoluto. Dentro de blocos `if`/`||`, o
`set -euo pipefail` não captura o exit non-zero (tratado como condição),
e o `2>/dev/null` mascarava "command not found".

Resultado: 8 tentativas × 20s de retry, todas falhando com exit 127
(command not found), mascarado como "storage não disponível".

**Correções anteriores (04/08) trataram o sintoma, não a causa:**
- Retry 3×10s → 5×15s → 8×20s — nunca ia resolver porque o problema
  era PATH, não concorrência pmxcfs
- `pvesm list` como primário no `if` — também não ajudou, mesmo
  comando que não está no PATH

**Causa raiz #2 — Token OAuth do Google Drive expirado:**

O `refresh_token` do rclone no CT 105 foi revogado pelo Google
(`invalid_grant`). O app está em "modo teste" no Google Cloud Console,
e o Google revoga refresh tokens de apps de teste após 7 dias sem uso.
Último upload bem-sucedido: 04/08 20:23. A partir de 05/08 02:00,
todos os uploads falham com "Token has been expired or revoked".

Tentativa de renovar via curl com o refresh_token atual também retornou
`invalid_grant` — o refresh token em si foi revogado, não apenas o
access token.

### Correções aplicadas

**Fix #1 — PATH nos 5 scripts (host vvy):**

Adicionado `export PATH=/usr/sbin:/usr/bin:/sbin:/bin` após `set -euo pipefail`
em todos os 5 scripts de backup do host:

- `/root/scripts/backup/snapshot_hermes.sh`
- `/root/scripts/backup/snapshot_semanal.sh`
- `/root/scripts/backup/snapshot_mensal.sh`
- `/root/scripts/backup/backup_proxmox_config.sh`
- `/root/scripts/backup/sync_root.sh`

Validação:
- `bash -n` (sintaxe) OK em todos os 5
- `env -i PATH=/usr/bin:/bin bash -c 'source script'` — pvesm list agora
  funciona na 1ª tentativa (antes: exit 127 "command not found")
- `env -i PATH=/usr/bin:/bin bash -c 'export PATH=...; pct status 105'` — OK
- Reexecução manual de snapshot_hermes às 12:53 — vzdump OK (4.0 GB, 1m48s),
  storage check OK na 1ª tentativa

**Fix #2 — Token OAuth (PENDENTE — requer browser):**

O refresh_token foi revogado. Para renovar:

1. Acessar URL de autorização no browser (URL gerada pelo agente)
2. Autorizar o app vvy-backup

5. Atualizar /root/.config/rclone/rclone.conf no CT 105

### Lições

1. **PATH do cron é /usr/bin:/bin, não /usr/sbin:/usr/bin:/sbin:/bin** —
   qualquer script que use `pvesm`, `pct`, `qm`, `pvesh`, `pveam` (todos em
   /usr/sbin) precisa de `export PATH=/usr/sbin:/usr/bin:/sbin:/bin` no
   topo. Sem isso, "command not found" é mascarado por `2>/dev/null` e
   `set -e` não captura dentro de `if`/`||`.

2. **As 3 correções anteriores (04/08) trataram o sintoma, não a causa** —
   retry 3→5→8 tentativas, `pvesm list` como primário, cron deslocado
   02:20→02:45. Nenhum disso ia resolver porque o problema era PATH. A lição:
   quando um fix "aumenta resiliência" mas o problema persiste, reexaminar
   a causa-raiz em vez de aumentar ainda mais o fix.

3. **Apps OAuth em modo teste do Google Cloud expiram em 7 dias** —
   refresh tokens de apps não publicados são revogados após 7 dias sem
   uso. Fix permanente: publicar o app (OAuth consent screen → publishing
   status → "In production"). Para uso pessoal sem verification,
   basta adicionar usuários de teste (até 100).
