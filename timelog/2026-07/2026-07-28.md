### Resgate da VM 200 (debian, <DOCKER_VM_IP>) — emergency mode

**O que foi feito:**
- VM 200 caiu em emergency mode no boot: `/dev/sdb: Can't open blockdev` com root locked (sem senha definida), bloqueando acesso ao console
- Causa raiz: linha `/dev/sdb /mnt/dados ext4 defaults 0 2` no `/etc/fstab` — mount por device path sem opção `nofail`. Quando o disco secundário não aparecia no boot, systemd travava
- Diagnóstico e correção feitos pelo host Proxmox (qm guest exec indisponível — agente não sobe em emergency mode):
  - Discos da VM montados como loopback no host (`losetup -fP`)
  - Disco principal (`scsi0`, nvme 32GB) montado em `/mnt/vm200-rescue`, fstab editado para comentar a linha problemática
  - VM reiniciada (`qm stop` + `qm start`), bootou normalmente
- Correções permanentes dentro da VM via `qm guest exec`:
  - `e2fsck -fp /dev/sdb` — journal recovery do disco secundário (estava com `needs journal recovery`)
  - fstab atualizado: device path substituído por `UUID=<VM200_DADOS_DISK_UUID>` com opção `defaults,nofail`
  - Senha do root definida (estava locked — status `L` em `passwd -S`)
  - Backup do fstab salvo em `/etc/fstab.bak.20260728`
- Estado final: VM running, `/mnt/dados` montado, `systemctl is-system-running` = running

**Documentos atualizados:**
- `docs/docker-vm.md` — nota de correção 28/07/2026 com detalhes do fstab (UUID + nofail), journal recovery e senha root

  - Imagem: `searxng/searxng:latest`
  - Config: `/root/searxng/docker-compose.yml` + `settings.yml`
  - Metasearch que agrega 70+ motores (Google, Bing, DDG, etc.)
  - Stateles, restart=unless-stopped
- Configurado Hermes Agent (CT 104) para usar SearXNG como backend de `web_search`:
  - `SEARXNG_URL=http://<DOCKER_VM_IP>:8888` adicionado ao `.env`
  - `web.backend: searxng` no `config.yaml` (`hermes config set web.backend searxng`)
- Testado: 40 resultados retornados na busca de teste via API JSON
- Considerado self-hostar Jina Reader (`ghcr.io/jina-ai/reader:oss`) na VM 200
  para web_extract (SearXNG é search-only):
  - Imagem baixada e container testado, mas **descartado** pela RAM limitada
    da VM 200 (3.8 GB alocados, Chrome headless do Jina consome ~500MB-1GB)
  - Container removido e imagem apagada (`docker rmi`)
  - Decisao: usar Jina Reader SaaS (`r.jina.ai`) via curl — grats, sem API key,
    sem self-hosting, zero RAM. Testado e funcionando.
- Benchmark de modelos NIM para pesquisa (tok/s):
  - nemotron-3-ultra-550b-a55b: 109 tok/s (melhor)
  - nemotron-3-super-120b-a12b: 86 tok/s
  - deepseek-v4-flash: 37 tok/s
  - mistral-medium-3.5-128b: 35 tok/s
  - deepseek-v4-pro: 12 tok/s (lento mas profundo)
