# 2026-07-31 — Hard Freeze Investigation (continuação)

## 06:42 — Hard freeze em idle (boot -2)

- Servidor estava em **idle absoluto** (load 0.11, 0.7% CPU, sem I/O, sem swap, sem OOM)
- Último log do kernel: 04:57:43 (1h45 de silêncio antes do freeze)
- kdump vazio, sem MCE, sem EDAC errors, sem panic
- Padrão: hard freeze puro sem logs — CPU parou de executar instantaneamente
- HandBrake NÃO estava rodando — exclui VRM sob carga como causa deste freeze

## Achado: ZFS module/userspace mismatch

- Módulo kernel `zfs.ko` + `spl.ko`: **2.4.2-pve1** (em `/lib/modules/6.17.13-19-pve/`)
- Pacote userspace `zfsutils-linux`: **2.4.3-pve1**
- Mismatch ativo desde 05/Jul (apt upgrade atualizou userspace mas não módulo)
- Módulo carregava **10 threads kernel** mesmo sem pools ZFS ativos:
  - `[arc_prune]` `[arc_evict]` x5 `[arc_flush]` `[arc_reap]` `[dbuf_evict]` `[l2arc_feed]`
- Hipótese: deadlock esporádico nas threads ARC/dbuf causa hard freeze sem logs em idle

## Ação corretiva — ZFS desativado

- `systemctl stop zfs-zed` → ZED parado (segurava o módulo "in use")
- `rmmod zfs` → módulo removido do kernel
- `rmmod spl` → SPL removido
- `echo "blacklist zfs/spl" > /etc/modprobe.d/blacklist-zfs.conf` → não carrega no boot
- `systemctl disable zfs-zed zfs-share zfs-import-cache zfs-import-scan` → serviços desativados
- Threads ZFS: **0** (antes eram 10)
- Servidor não usa ZFS (root é LVM, zero pools, zero datasets)

## imagemagick/ffmpeg — descartado

- `apt install imagemagick ffmpeg` em 30/Jul 16:55 foi para skills de photo (exif/raw compress)
- Libs de userspace — não tocam kernel, não regeneraram initramfs do -19
